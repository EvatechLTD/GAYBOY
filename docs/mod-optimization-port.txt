MOD optimization port to main - 21 October 2026

Status

Ported to main as extracted changes, without importing the dispatch branch.
Functional checks below passed. Performance validation is mixed:
there are measured CPU/timing regressions as well as substantial savings. This is
not a clean timing acceptance pass and does not establish hardware reliability.

Changes

1. evaluation.c: exact synced-LFO quotient/remainder caching; preserve the
   frame timebase, musical clock wrap, clamp, retriggers and envelope cadence.
   Settings changes seed the fraction from the retained musical clock.
   Long gaps use binary accumulation, bounded to eight iterations, rather than
   dispatch's potentially 255 frame iterations. Free-rate clock catch-up is
   batched too. Neither path does hidden elapsed-time work while idle.

2. evaluation.c/global.c: independent configured LFO/envelope route masks and
   live activity/ownership checks. Both signed fine and coarse depths and their
   independent source selectors count; ADSR volume counts without pitch depth.
   Native voices 0..3, noise 5/6 and kick 7 are included. Slot 4 is mixer gains,
   not a voice. PCM, kick and noise ownership excludes displaced native voices.
   LFO-only notes do not start the envelope. Route removal clears held-envelope
   users and starts a remaining tail's release when the last held user vanishes.
   The last configured LFO route resets phase/clock; adding another route to an
   already configured LFO preserves phase. Inactive consumers pause free phase.
   pattern_generation handles UI, MIDI/program and user-preset mutation paths;
   defaults/eval restore dirty the cache explicitly. coarse_restore also dirties
   it, covering the independently restored coarse destinations.
   Zero-depth waveform evaluation already short-circuited on main.

3. evaluation.c: eval_arp_wait/eval_seq_tick exclude empty chords before clock
   or period work. Main's existing scheduler still wakes song rows and gates.
   Empty clocks pause. Chord rebuilds wake arps with retain/retrigger rules intact.

No chord staging, alternate timer, storage rewrite, attack fast path or capacity
reduction was imported. Main's scheduler, storage format and memory map remain.

All commands completed. The compare command records measurements, not a timing
pass: its JSON preserves timing_target_met and foreground_load_exercised flags.

The LFO test made 1,836 exact baseline/candidate phase/clock comparisons: all 17
divisions and 3 timings; BPM changes, sync/free switching, retriggers, clock wrap,
zero-frame updates and gaps including the binary-path boundaries and 255 frames.
The test documents the main-specific private-state offsets; they must be updated
if the leading evaluation object layout changes.

The arp test matched 47 populated configurations (all 11 orders, straight/triplet/
dotted/free-ms clocks and retained phase). Additional tests empty and rebuild a
song chord and check paused/resumed clocks with retrigger both off and on.

The idle test covered 28 signed fine/coarse/source/voice combinations plus mixed
sources, no engine/audio calls when unused, zero-to-nonzero wakeup, free-phase
pause, source edits during a note, release tails, overlapping held voices, actual
overlapping MIDI keys, native ownership exclusions, tone restore, user-preset
restore and defaults. Raw fixture writes dirty the route cache explicitly or
increment pattern_generation.

ROM-bank, SRAM/WRAM and stack-reservation checks passed. Ordinary WRAM use grew

The 512-byte stack reservation remains. Attack-write stack samples stayed at or
above DF50 in these workloads; this is sampling, not a full stack watermark test.

There are observed regressions of about 0.75 ms in the arp case, 1.94 ms in the
PCM case and 7.92 ms in the drawing-load case. The LFO stress peak improves by
about 10.89 ms. These short deterministic emulator runs are not worst-case bounds.

The 60 BPM drawing case exercised 59 baseline and 62 candidate stall calls.
The high-load arp/LFO/PCM runs exercised none, so they lack drawing-load coverage.
The 300 BPM native comparison improved idle/navigation peak from 9.482 to 8.169
ms, but its stall phase had zero baseline stalls and one candidate stall (40.230
ms error); that phase is not an equivalent-load comparison or a coverage pass.
All paired cases recorded zero PCM underruns. None met the 4 ms timing target.

The imported dispatch timing harness initially hooked all local/stack writes in
play; that made one candidate navigation run hang in PyBoy. The main adaptation
hooks the emitted BC pulse-trigger writes and direct wave/noise writes instead,
and checks their counts against play entry counts. With that coverage assertion,
all paired measurement commands complete. Measurement-mode incomplete drawing
coverage remains explicit rather than being silently accepted as a pass.
